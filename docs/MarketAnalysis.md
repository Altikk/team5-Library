# 3. Инсайты и требования

Метод: **Инсайт → Потребность → Требование → Критерий приёмки**.

## Инсайт 1. Отзывы накручивают в обе стороны

| Шаг         | Содержание |
| ----------- | ---------- |
| Инсайт      | На LiveLib авторы жалуются на однотипные хвалебные «заказные» рецензии; на Goodreads — массовые 1★ (review bombing) от новых и фейковых аккаунтов, даже до выхода книги. |
| Потребность | Читателю нужны отзывы, которым можно доверять; системе — защита от накрутки опыта и рангов. |
| Требование  | Опыт за отзыв начисляется **с задержкой** (после периода, в который можно пожаловаться) и с **суточным лимитом**; опыт за лайки от одного и того же пользователя автору ограничен. |
| Критерий    | Запись в `experience_log` с `Reason = review_created` появляется не раньше чем через 72 ч после публикации и только если отзыв в статусе `active`; суммарное начисление одному пользователю ≤ 100 XP в сутки (тест: 10 отзывов за день → начислено не больше лимита). |
| MoSCoW      | Must — M7 |

## Инсайт 2. Ранг ценен, только если влияет на то, что видит читатель

| Шаг         | Содержание |
| ----------- | ---------- |
| Инсайт      | У Фантлаба классы дают только права на форуме/в классификации, а читатель отзыва их почти не замечает. У Яндекс «Знатоков» высокий уровень прямо повышает охват отзыва — и это главный стимул писать. |
| Потребность | Читатель хочет сначала видеть мнения опытных авторов; автор хочет, чтобы его рост был заметен. |
| Требование  | По умолчанию отзывы на карточке книги сортируются **по рангу автора (убыв.), затем по дате (новые выше)**; рядом с именем — бейдж ранга. Доступна переключаемая сортировка «по дате». |
| Критерий    | На карточке книги с ≥ 10 отзывами первые 5 отзывов принадлежат авторам с максимальными рангами среди отзывов книги; у каждого отзыва отображается бейдж с `ranks.Title`; переключение сортировки ≤ 1 клика. |
| MoSCoW      | Must — M8, M9 |

## Инсайт 3. Если платить за количество — получишь короткие отзывы

| Шаг         | Содержание |
| ----------- | ---------- |
| Инсайт      | У Яндекса баллы фиксированы за любой отзыв; Фантлаб, наоборот, начисляет за отзыв 0,1–10 баллов в зависимости от длины — это стимулирует развёрнутые рецензии. |
| Потребность | Читателю нужен содержательный отзыв, а не «понравилось, 5★». |
| Требование  | Опыт за отзыв зависит от его объёма и отклика: базовое начисление только для текста ≥ 300 символов; дополнительный опыт — за лайки других пользователей. Оценка без текста опыта не даёт. |
| Критерий    | Отзыв < 300 символов публикуется, но в `experience_log` записывается 0 XP; отзыв 300–999 символов — +20 XP, ≥ 1000 символов — +35 XP (карточка, раздел 5.16); каждый лайк — отдельная запись `like_received` (+2 XP). |
| MoSCoW      | Must — M6, M7 |

## Инсайт 4. Модерация не успевает за всплесками

| Шаг         | Содержание |
| ----------- | ---------- |
| Инсайт      | Goodreads признал, что реагирует на атаки на книги медленно, и пообещал ограничивать отзывы при «необычной активности». |
| Потребность | Модератору нужно быстро увидеть подозрительный отзыв; автору — прозрачная причина скрытия. |
| Требование  | Отзыв, набравший ≥ 3 открытых жалоб от разных пользователей, автоматически попадает в начало очереди модерации; каждое действие модератора (hide / restore / delete / penalty) пишется в `moderation_log` с причиной; при `penalty` автору списывается опыт. |
| Критерий    | Тест: 3 жалобы от разных аккаунтов → отзыв в очереди с пометкой «приоритет»; любое действие модератора создаёт запись в `moderation_log` с непустым `Reason`; при `penalty` в `experience_log` появляется запись с отрицательным `Amount`. |
| MoSCoW      | Must — M11, M12 |

## Инсайт 5. Доверие к рангам требует прозрачных правил

| Шаг         | Содержание |
| ----------- | ---------- |
| Инсайт      | Фантлаб публикует полную таблицу порогов классов и баллов за каждое действие — пользователи понимают, как растёт статус. У LiveLib и Goodreads неясно, почему одни отзывы выше других. |
| Потребность | Читатель должен понимать, что значит ранг; автор — как его повысить. |
| Требование  | Публичная страница «Как работают ранги», доступная гостю: список рангов с порогами опыта и правила начисления/списания. В личном кабинете — прогресс до следующего ранга. |
| Критерий    | Страница открывается без авторизации, содержимое формируется из таблицы `ranks` (изменение порога в БД сразу отражается на странице); в профиле отображается «N из M XP до ранга X». |
| MoSCoW      | Must — M10 |

# 4. Выводы для проекта

1. **Наша ниша подтверждена**: ни один крупный книжный сервис не связывает репутацию автора с видимостью его отзыва. Такой паттерн есть у Яндекса, но в другой области.
2. **Главный риск всех аналогов — накрутка.** Значит, антинакрутка не «дополнительная фича», а основа ценностного предложения: она должна быть в MVP.
3. **Не копируем** соцфункции LiveLib и Goodreads (ЛС, ленты, челленджи). Они не решают задачу «выбрать книгу по надёжному отзыву» и уже вынесены в Won't have.
4. **Холодный старт**: на запуске мало отзывов. Это решаем импортом каталога из открытых API (Could have) и привлечением активных рецензентов как отдельного сегмента (см. Vision).
