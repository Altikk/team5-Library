## 1. Обоснование проекта

Читатели выбирают книги по средним оценкам и отзывам, но этим данным всё меньше доверяют. На LiveLib встречаются однотипные хвалебные «заказные» рецензии, на Goodreads — массовые атаки единицами (review bombing). Ни один крупный книжный сервис не связывает репутацию автора отзыва с тем, насколько заметен его отзыв (см. [MarketAnalysis.md](MarketAnalysis.md)).

**Бизнес-цель:** создать авторитетную рекомендательную платформу за счёт уникальной системы отзывов, увеличить продажи партнёров и открыть дополнительные возможности для монетизации.

## 4. Рамки проекта

**Входит:** функции из раздела Must в [MoSCoW.md](MoSCoW.md). Во втором семестре — Should и выбранные Could.

**Не входит:** мобильное приложение, продажа книг и встроенная читалка, платная подписка и внутренняя валюта, социальная лента и личные сообщения, AI-рекомендации, учёт продаж внутри сервиса (это делает 1С партнёра).

Подробные границы и внешние системы описаны в [Vision.md](Vision.md), раздел 5.

3. Пакет документации сдан полностью и согласован между собой.
4. MVP и итоговая версия успешно защищены.

## 11. Управление проектом

- **Коммуникации:** еженедельная встреча команды (статус, блокеры, план), чат команды для оперативных вопросов, отчёт куратору на каждой практике.
- **Инструменты:** Git-репозиторий (код + документация в Markdown), трекер задач (доска по этапам календаря).
- **Управление изменениями:** любое изменение границ согласует Team-Lead. Сначала обновляется MoSCoW, затем карточка, с повышением версии и записью «Изменения vX». Изменения, затрагивающие Must после 17.11.26, согласуются с куратором.
- **Контроль качества:** код-ревью минимум одним участником, проверка согласованности документов перед каждой сдачей.

## 12. Допущения и ограничения

**Допущения:** пользователи готовы писать отзывы ради ранга; ранг авторитетен для читателей; данные о книгах доступны из открытых источников.

**Ограничения:** срок MVP — до 22.12.26; только веб-версия; нулевой бюджет; состав команды фиксирован.
