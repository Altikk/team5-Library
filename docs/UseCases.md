## 1. Список акторов

| Код | Актор | Тип | Описание | Сегмент / роль в `roles` |
| --- | ----- | --- | -------- | ------------------------ |
| A1 | **Гость** | Основной, человек | Незарегистрированный посетитель: ищет книги, читает отзывы, смотрит правила рангов | Сегмент А, роль `guest` |
| A2 | **Читатель** | Основной, человек | Зарегистрированный пользователь: всё, что может гость, плюс отзывы, лайки, жалобы, профиль. Читатель, который пишет отзывы, — это рецензент (сегмент Б). Отдельной роли для него нет, отличается только рангом | Сегменты А и Б, роль `reader` |
| A3 | **Модератор** | Основной, человек | Обрабатывает жалобы, скрывает, восстанавливает и удаляет отзывы, назначает штрафы | Роль `moderator` |
| A4 | **Администратор** | Основной, человек | Управляет пользователями и ролями, настраивает ранги и правила опыта | Роль `admin` |
| A5 | **Планировщик** | Вспомогательный, системный (время) | Внутренний таймер: по расписанию подтверждает отложенный опыт и пересчитывает ранги | — |
| A6 | **1С партнёра** | Внешняя система | Учётная система магазина или издательства: получает каталог, возвращает отчёт по продажам | Сегмент В |
| A7 | **Email-сервис** | Внешняя система | Отправляет письма: подтверждение регистрации, восстановление пароля | — (Should) |
| A8 | **Открытые API книг** | Внешняя система | Google Books / Open Library: источник данных для каталога | — (Could) |

Иерархия: **Администратор ⊃ Модератор ⊃ Читатель ⊃ Гость** (каждая следующая роль наследует возможности предыдущей).

## 4. Описание Use Case

### UC-01. Зарегистрироваться и войти

| Поле | Описание |
| ---- | -------- |
| Актор | Гость |
| Цель | Получить учётную запись, чтобы писать отзывы и копить опыт |
| Предусловия | Пользователь не авторизован |
| Основной поток | 1. Гость нажимает «Регистрация». 2. Вводит логин, email, имя, пароль. 3. Система проверяет уникальность логина и email и сложность пароля. 4. Система создаёт запись в `users` (`RoleID = reader`, `RankID = 1`, `Experience = 0`), хэширует пароль. 5. Система авторизует пользователя (сессия/JWT) и возвращает его на исходную страницу. |
| Альтернативы | 3а. Логин или email заняты — система показывает ошибку у поля. 6а. Вход: пользователь вводит логин и пароль, система сверяет хэш и выдаёт сессию. 6б. Неверный пароль 5 раз подряд — вход блокируется на 15 минут. |
| Постусловия | Пользователь авторизован с ролью «Читатель» и рангом «Новичок» |
| Требования | M1, M2 |

### UC-02. Найти и выбрать книгу

| Поле | Описание |
| ---- | -------- |
| Актор | Гость или Читатель |
| Цель | Быстро найти книгу и прочитать самые надёжные отзывы о ней |
| Предусловия | Каталог заполнен |
| Основной поток | 1. Пользователь открывает каталог. 2. Вводит запрос и/или задаёт фильтры (жанр, автор, год). 3. Система показывает список книг с обложкой и средним рейтингом. 4. Пользователь открывает карточку книги. 5. Система показывает описание, средний рейтинг и отзывы со статусом `active`, отсортированные по рангу автора (по убыванию), затем по дате; у каждого отзыва есть бейдж ранга. 6. Пользователь читает отзывы и принимает решение. |
| Альтернативы | 3а. Ничего не найдено — система предлагает сбросить фильтры. 5а. Пользователь переключает сортировку на «по дате» (1 клик). 5б. Отзывов нет — показывается приглашение написать первый отзыв. |
| Постусловия | Пользователь увидел карточку и отзывы; данные не меняются |
| Критерий | От открытия каталога до прочтения первого отзыва — ≤ 30 с (метрика 1 Vision) |
| Требования | M3, M4, M8, M9 |

### UC-03. Опубликовать, отредактировать или удалить отзыв

| Поле | Описание |
| ---- | -------- |
| Актор | Читатель |
| Цель | Поделиться мнением о книге и получить опыт |
| Предусловия | Пользователь авторизован; у него нет отзыва на эту книгу |
| Основной поток | 1. Читатель на карточке книги нажимает «Написать отзыв». 2. Ставит оценку 1–5 и пишет текст. 3. Система проверяет, что отзыва от этого пользователя на книгу ещё нет. 4. Система сохраняет отзыв (`Status = active`) и пересчитывает `books.AvgRating` и `ReviewsCount`. 5. Если текст ≥ 300 символов, система создаёт запись `experience_log` (`review_created`, +20 или +35, `Status = pending`, `ConfirmAt = +72 ч`) — включает UC-07. 6. Система показывает отзыв на карточке и сообщение «Опыт будет начислен через 72 ч». |
| Альтернативы | 3а. Отзыв уже есть — система предлагает его отредактировать. 5а. Текст < 300 символов — отзыв публикуется, опыт не начисляется, пользователь видит подсказку. 7а. Редактирование: обновляется `UpdatedAt`, рейтинг книги пересчитывается, опыт не меняется. 7б. Удаление автором: `Status = deleted`, неподтверждённая запись опыта переходит в `cancelled`, рейтинг книги пересчитывается. |
| Постусловия | Отзыв опубликован; опыт ожидает подтверждения |
| Требования | M5, M7 |

### UC-04. Оценить отзыв (лайк)

| Поле | Описание |
| ---- | -------- |
| Актор | Читатель |
| Цель | Отметить полезный отзыв и поднять опыт его автора |
| Предусловия | Пользователь авторизован; отзыв не его |
| Основной поток | 1. Читатель нажимает «Полезно» у отзыва. 2. Система создаёт запись `review_likes` и увеличивает `LikesCount`. 3. Система сразу начисляет автору +2 XP (`like_received`, `Status = confirmed`), если не превышены лимиты: 10 XP в сутки от одного лайкающего и 100 XP в сутки всего. |
| Альтернативы | 1а. Повторное нажатие снимает лайк: запись удаляется, `LikesCount` уменьшается, начисленный за этот лайк опыт списывается (запись `like_received` с `Amount = −2`). 3а. Лимит превышен — лайк засчитывается, опыт не начисляется. |
| Постусловия | Лайк учтён; опыт автора обновлён в пределах лимитов |
| Требования | M6, M7 |

### UC-05. Пожаловаться на отзыв

| Поле | Описание |
| ---- | -------- |
| Актор | Читатель |
| Цель | Сообщить о недопустимом или накрученном отзыве |
| Предусловия | Пользователь авторизован; отзыв не его; жалобы от него на этот отзыв ещё нет |
| Основной поток | 1. Читатель нажимает «Пожаловаться». 2. Выбирает причину (спам / оскорбления / спойлер без пометки / не по теме / накрутка) и при желании добавляет комментарий. 3. Система создаёт запись `reports` (`Status = open`). 4. Если у отзыва ≥ 3 открытых жалоб от разных пользователей, система поднимает его в начало очереди модерации с пометкой «приоритет». |
| Альтернативы | 3а. Жалоба от этого пользователя уже есть — система сообщает, что жалоба на рассмотрении. |
| Постусловия | Жалоба в очереди модерации |
| Требования | M11 |

### UC-06. Модерировать отзыв

| Поле | Описание |
| ---- | -------- |
| Актор | Модератор |
| Цель | Убрать недопустимый контент и наказать накрутку |
| Предусловия | Пользователь авторизован с ролью `moderator` или `admin`; в очереди есть жалобы |
| Основной поток | 1. Модератор открывает очередь (сначала приоритетные отзывы, затем по дате жалобы). 2. Открывает отзыв с жалобами. 3. Выбирает действие: скрыть, восстановить, удалить или оштрафовать, и указывает причину (обязательно). 4. Система меняет `reviews.Status`, пересчитывает `books.AvgRating` и `ReviewsCount` (скрытые и удалённые отзывы не учитываются), пишет запись в `moderation_log` и переводит связанные жалобы в `resolved`. 5. При действии `penalty` система списывает −50 XP и отменяет неподтверждённый опыт за отзыв (расширяет UC-07). |
| Альтернативы | 3а. Жалоба необоснованна — модератор отклоняет её, жалобы получают `rejected`, отзыв остаётся `active`. 3б. Причина не указана — система не даёт сохранить действие. |
| Постусловия | Отзыв обработан; действие записано в журнал |
| Критерий | 90 % жалоб обработаны за ≤ 24 ч (операционная метрика Vision) |
| Требования | M2, M12 |

### UC-07. Подтвердить начисление опыта и пересчитать ранг

| Поле | Описание |
| ---- | -------- |
| Актор | Планировщик |
| Цель | Начислить опыт только за отзывы, которые прошли период жалоб |
| Предусловия | В `experience_log` есть записи `pending` с наступившим `ConfirmAt` |
| Основной поток | 1. Планировщик запускается раз в час. 2. Система выбирает записи `pending` с `ConfirmAt ≤ сейчас`. 3. Для каждой проверяет, что исходный отзыв в статусе `active` и суточный лимит 100 XP не превышен. 4. Переводит запись в `confirmed` и увеличивает `users.Experience`. 5. Пересчитывает `users.RankID` по таблице `ranks`. |
| Альтернативы | 3а. Отзыв скрыт или удалён — запись переходит в `cancelled`. 3б. Лимит превышен — подтверждение переносится на следующие сутки. 5а. После штрафа опыт ниже порога — ранг понижается. |
| Постусловия | Опыт и ранг пользователя актуальны |
| Требования | M7 |

### UC-08. Обменяться данными с 1С

| Поле | Описание |
| ---- | -------- |
| Актор | 1С партнёра (инициатор по расписанию); Администратор (ручной запуск) |
| Цель | Передать партнёру каталог со статистикой отзывов и получить отчёт по продажам |
| Предусловия | Настроены адрес обмена и ключ доступа партнёра |
| Основной поток | 1. 1С запрашивает у КнигоПоиска каталог (книги, авторы, жанры, `AvgRating`, `ReviewsCount`) через защищённый API в формате JSON. 2. Система отдаёт данные и фиксирует факт выгрузки. 3. 1С передаёт отчёт по продажам за период (книга, количество, сумма). 4. Система проверяет формат, сохраняет отчёт и показывает его администратору. |
| Альтернативы | 1а. Неверный ключ — система отклоняет запрос (401). 4а. Ошибка формата — отчёт отклоняется с описанием ошибки, администратор видит неудачную попытку. |
| Постусловия | Каталог в 1С актуален, отчёт по продажам доступен в системе |
| Требования | M13 |

### UC-09 – UC-11 (кратко)

| Код | Основной поток |
| --- | -------------- |
| UC-09 | Пользователь открывает «Как работают ранги» и видит таблицу рангов из `ranks` и правила начисления. Авторизованный пользователь в профиле видит свой ранг и прогресс «N из M XP до ранга X» |
| UC-10 | Администратор находит пользователя, меняет его роль (например, назначает модератором) или блокирует (`IsActive = false`); может изменить пороги рангов |
| UC-11 | (Could) Администратор задаёт ISBN или запрос, система загружает данные книги из открытого API, администратор подтверждает добавление |
