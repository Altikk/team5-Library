# Vision продукта — КнигоПоиск

| **Поле**  | **Описание**                                                        |
| --------- | ------------------------------------------------------------------- |
| Проект    | КнигоПоиск (Онлайн-сервис выбора книг с уникальной системой оценки) |
| Документ  | Vision (Практика 2)                                                 |
| Версия    | v1.1 (синхронизировано с MoSCoW v2.0 и карточкой v1.4)              |
| Дата      | 20.10.26                                                            |

## 1. Vision Statement

> **Для** читателей, выбирающих следующую книгу, **которым нужно** быстро найти честное и содержательное мнение, а не накрученную среднюю оценку,
> **продукт** КнигоПоиск — **это** веб-сервис выбора книг и отзывов,
> **который** первыми показывает отзывы авторов с заслуженной репутацией благодаря прозрачной системе опыта и рангов.
> **В отличие от** LiveLib и Goodreads, где все отзывы равны и легко накручиваются, **наш продукт** ранжирует отзывы по рангу автора, а сам рост ранга защищён от накрутки задержкой начисления, лимитами и модерацией.

## 2. Проблема пользователя

- Средний рейтинг книги ничего не говорит: его искажают и заказные хвалебные отзывы, и массовые атаки 1★ (подтверждено анализом LiveLib и Goodreads).
- Отзывы показываются вперемешку. Чтобы найти содержательную рецензию, нужно пролистать десятки «понравилось, 5★».
- У тех, кто пишет хорошие отзывы, нет стимула продолжать: их вклад визуально не отличается от остальных.

## 3. Целевая аудитория

| Сегмент | Описание | Сценарий | Роль в MVP |
| ------- | -------- | -------- | ---------- |
| **А. Выбирающий читатель** | 18–35 лет, читает 1–3 книги в месяц, перед покупкой или чтением ищет мнения о книге | Найти книгу в каталоге → прочитать 2–3 отзыва от опытных авторов → принять решение | **Основной сегмент MVP**: под него проектируются каталог, карточка книги и сортировка отзывов |
| Б. Активный рецензент | Пишет отзывы регулярно, ему важны признание и статус | Написать отзыв → получить опыт и лайки → вырасти в ранге | Поставщик контента: без него у сегмента А нет ценности. В MVP — регистрация, отзывы, опыт, ранги |
| В. Партнёр (книжный магазин / издательство) | B2B: использует данные о спросе и отзывах | Получить выгрузку каталога и отчёт по продажам через 1С | Вторичный, демонстрация монетизации (интеграция с 1С, этап 7) |

**Почему основной — А:** бизнес-цель — стать авторитетной рекомендательной платформой и увеличить продажи. Продажи создаёт тот, кто выбирает книгу. Рецензенты (Б) — средство создать для него ценность, поэтому система рангов проектируется с точки зрения «что увидит читатель».

## 4. Ценностное предложение

- **Для читателя:** лучшие отзывы наверху, а бейдж ранга сразу показывает, насколько автору можно доверять.
- **Для рецензента:** заметный и честный рост. Ранг поднимает его отзывы выше, а правила роста открыты.
- **Для партнёра:** аудитория, которая приходит выбирать книгу, и данные о спросе через 1С.

## 5. Границы системы

### 5.1 Входит в границы (MVP)

| ✓ | Пункт |
| - | ----- |
| ✓ | Регистрация и авторизация, роли (гость, читатель, модератор, администратор) |
| ✓ | Каталог книг с поиском и фильтрами (жанр, автор, год) |
| ✓ | Карточка книги: описание, обложка, средний рейтинг |
| ✓ | Создание, редактирование и удаление отзыва (один отзыв на книгу от пользователя) |
| ✓ | Лайки отзывов |
| ✓ | Начисление опыта и присвоение ранга с защитой от накрутки: задержка 72 ч, суточный лимит 100 XP, зависимость от объёма отзыва (карточка, раздел 5.16) |
| ✓ | Бейдж ранга у отзыва и сортировка отзывов по рангу и дате |
| ✓ | Публичная страница правил рангов и базовый профиль с прогрессом до следующего ранга |
| ✓ | Модерация: жалобы, очередь, скрытие и удаление, журнал `moderation_log`, штраф опытом |
| ✓ | Обмен с 1С партнёра: выгрузка каталога, приём отчёта по продажам (сама 1С — внешняя система) |

### 5.2 Не входит в границы

| ✕ | Пункт | Почему |
| - | ----- | ------ |
| ✕ | Мобильное приложение | MVP — только веб |
| ✕ | Продажа книг на платформе и встроенная читалка | Мы помогаем выбрать, а не продаём и не даём читать (это делают Литрес и магазины) |
| ✕ | Платная подписка и внутренняя валюта | Монетизация через B2B-партнёров, а не через читателя |
| ✕ | Социальная лента, личные сообщения, читательские челленджи | Соцфункции LiveLib и Goodreads не решают задачу выбора книги |
| ✕ | AI-рекомендации и генерация отзывов | Противоречит идее доверия к живым авторам |
| ✕ | Учёт продаж и складской учёт внутри сервиса | Это остаётся на стороне 1С партнёра, мы только обмениваемся данными |

### 5.3 Внешние системы на границе

- **1С** (партнёр): обмен каталогом и отчётами по продажам. Это отдельная система: мы интегрируемся с ней, но не реализуем её функции.
- **Email-сервис**: подтверждение и восстановление пароля (Should have).
- **Открытые API книг** (Google Books / Open Library): источник данных для каталога (Could have).

## 6. Метрики успеха

| № | Метрика | Целевое значение | Как измеряем |
| - | ------- | ---------------- | ------------ |
| 1 | **Время до полезного отзыва**: от открытия каталога до прочтения первого отзыва на нужную книгу | ≤ 30 секунд у ≥ 80 % участников | Юзабилити-тест на демо-стенде (≥ 5 респондентов) со сценарием «найди книгу X и реши, читать ли её» |
| 2 | **Качество рангов**: доля отзывов авторов высших рангов (5–6: «Знаток», «Эксперт»), скрытых или удалённых модерацией | ≤ 2 % (против среднего по всем отзывам) | Запрос к `reviews` + `moderation_log` + `users.RankID` за период тестирования |
| 3 | **Удержание рецензентов**: доля пользователей, которые после первого отзыва написали второй в течение 30 дней | ≥ 30 % | Когортный запрос к `reviews` по `UserID` и `CreatedAt` |

Дополнительная операционная метрика: 90 % жалоб обрабатываются модератором за ≤ 24 ч (`reports.CreatedAt` → запись в `moderation_log`).

## 7. Ограничения и допущения

**Ограничения:**

- Срок MVP — до защиты 15.12.26–22.12.26. Команда — 5 человек.
- Только веб-версия. Интеграция с 1С запланирована в MVP (этап 7 календаря, требование M13).
- Обложки и описания книг используются с учётом авторских прав (открытые источники или права партнёров).
- Обработка персональных данных (email) — по пользовательскому соглашению.

**Допущения:**

- Пользователи готовы писать отзывы ради роста ранга.
- Ранг авторитетен для читателей при выборе книги. Проверяется метриками 1 и 2.
- Данные о книгах можно получить из открытых источников или API.
- Для холодного старта на демо-стенд можно загрузить тестовые отзывы и пользователей с разными рангами.
